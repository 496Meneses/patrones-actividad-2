1.Escenario
Tipo Patron: Creacional
Patron: Builder
Justificación: Dado el problema, para construir un automovil, se requiere un conjunto de pasos,  esto se logra mediante objetos builders sin necesidad de tener subclases o constructores con una cantidad alta de parámetros. Mediante objetos builders se logra separar de 1 solo objeto que contenga toda la lógica para construir distintos tipos de automoviles, en varios objetos que resuelvan personalizaciones.

2.Escenario
Tipo Patrón: Estructural
Patrón: Patrón Bridge
Justificación: El patrón bridge separa muy bien la jerarquía de clases que hay entre Tipos de dispositivos y tipos de notificaciones, Evitando crear muchas clases como resultado de las combinaciones entre las dos jerarquías.


3.Escenario
Tipo Patrón: Comportamiento
Patrón: Patrón Mediador
Justificación: El patrón mediador es muy útil en estos casos, donde multiples objetos necesitan interacturar entre si, permitiendo centralizar la comunicacion y evitar el acoplamiento entre ellos. 


Nota: Los diagramas de cada escenario estan en la carpeta UML.
